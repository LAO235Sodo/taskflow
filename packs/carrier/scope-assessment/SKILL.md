# scope-assessment — 范围与容量评估

能力契约（依赖倒置：引用方依赖本接口，不依赖实现）：输入=需求描述+候选改动面；输出=改动面枚举+容量对照+超限处置。

## 执行清单

1. **输入**：需求一句话 + 候选改动面（页面清单/模块名/接口名，可先粗后细）。
2. **三层递进枚举**（产出「N 页面 / M 接口 / K 文件」）：
   - 页面层：触达哪些页面/入口（新增标注「新增」）；
   - 接口层：每页面对应的后端接口/数据契约（新增/改口径分开计数）；
   - 文件层：预计动的源码文件清单（目录粒度可接受，但须可数）。
3. **单会话容量对照**（三档判定）：
   - 小：≤3 页面或 ≤8 文件——单会话可完成；
   - 中：4~8 页面或 9~20 文件——单任务可完成，须 checkpoint 分段；
   - 大：>8 页面或 >20 文件——超限，禁硬塞。
4. **超限处置**（决策树，呈用户拍板）：
   - 可垂直切（按页面/模块独立交付）→ 拆分为 N 个任务，写明顺序依赖；
   - 不可垂直切 → 与用户砍范围（先交付子集）或显式接受多会话长任务（large 档）。
5. **输出**：枚举表 + 容量结论 + 拆分建议，落 spec「边界与影响面」节（`tf.mjs new` 渲染后由编排层填）。

## 边界

- 只评估不实施；评估结论须可证伪（文件清单可被 grep 复核）。
- 与 impact-analysis 分工：本技能管「动手前的预期面」，彼管「改动集的实际牵连面」。
