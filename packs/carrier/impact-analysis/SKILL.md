# impact-analysis — 变更影响盘点

能力契约：输入=改动集（文件/函数/字段/口径）；输出=消费方清单+牵连模块表。对应纪律「变更影响盘点」——动手前列消费方，逐方核对影响。

## 执行清单

1. **输入**：改动集（本次要改的文件/符号/字段口径，含 bug 修复与「小改动」）。
2. **消费方清单**（逐条 文件:行号 + 消费性质）：
   - grep/引用检索每个被改符号（函数名/字段名/枚举值/事件名）；
   - 消费性质分类：读（展示）/写（赋值）/分支（判断逻辑）/契约（对外接口或存储格式）；
   - 机械辅助：`node <taskflow>/scripts/tf.mjs impact --files <f1,f2>`（basename 引用计数）可用则跑，语义级仍需人工。
3. **牵连模块表**：消费方按模块归组，标注「需同步改 / 需回归测 / 无影响——理由」。
4. **「修一处全链生效」证明**：消费方多点分布 = 逐点同步改；清单为空才可宣称无影响。
5. **输出**：清单落 spec「边界与影响面」或 findings.md；修复类任务另跑同类排查（同模式 grep 还有几处）。

## 边界

- 禁以「展示层/纯文案」自我豁免——是否纯展示由清单判定。
- 与 scope-assessment 分工：彼管动手前预期面，本技能管实际改动集的下游牵连。
