# frontend 包 — 前端视觉门族

> 能力包（v3.0.0）：本包含前端视觉/原型方向的全部规则与机械面。核心 SKILL.md 只留一行通用纪律（渲染产物 fixture 必须真执行 + 变更影响盘点）；本包细则仅当项目 profile `packs.frontend=true`（或任务类型未禁用）时加载。
> 安装产物：`node <skill目录>/scripts/tf.mjs mech install STYLE_SOURCE_GATE`（六产物：提取器×2 + 门脚本×4）。

## 规则全文

### 规则：前端方向呈报必须附可视化载体 + 标准先行真渲染自查（原硬规则 11）

涉及前端页面/布局/视觉的方案呈报、方向变更建议，**纯文字 = 呈报不合格，用户可直接打回**。载体按改动类型选档：
- **已有页面修改（返工/调整）→ 强制「基于线上实况的 HTML 变更方案稿」**：现状从线上机械提取（现状基线门或线上截图裁片；线上发过新版旧基线作废必须重提，禁旧基线/记忆当现状），变更区域做成可渲染 HTML delta（样式值取现状基线规格表），真渲染自查 + 用户过目拍板后方可实现/部署；文字线框图/纯截图标注档在此场景不再合格。
- **全新页面（无现状可依）**：走原型六步链（见「原型流程」节）。
- **视觉配色小改**：静态 HTML 设计稿（须真渲染）。

**自查硬流程**：呈报前先制定设计自查标准（用户参考对象特征 + 系统既有设计语言 + 已拍板决策），真渲染截图逐项核对（结构对齐/数据正确性/渲染健康零 error/样式一致性/交互完整性/环境干扰排除），全项通过才呈报，呈报附「标准+逐项核对结果」；IA 类歧义（独立入口 vs 页内切换）必须在自查阶段问用户拍板。

**视觉变更的判定不由模型自判**：凡 diff 触及样式块（`<style>` 段）、`@media` 查询、视图组件样式类——含删除与机制回退——一律视为视觉变更，强制真渲染前后对照；「删样式=无视觉变化」不构成豁免；机制删除/回退类任务的同类排查锚点=机制载体指纹（媒体块/类名/属性）全仓 grep。

### 规则：前端视觉事实禁止目测定案（原硬规则 13）

凡可程序采样的渲染事实（球色/命中状态/连线归属/位置尺寸），禁止凭"看截图觉得对"下结论——必须 DOM 定位（`getBoundingClientRect` 取球心）× devicePixelRatio 映射到截图像素坐标，采样实际色值与预期比对（容差），采样证据（元素→坐标→采样值→预期值）随呈报/验收记录附上；仅无法采样的事实（整体布局观感）允许目测且注明「目测」。采样要点与陷阱（DPR/滚动偏移/canvas 坐标系/抗锯齿/夜间模式）见包内 `prototype-selfcheck.md`「术语化规范」。

### 规则：原型→规格表机械提取（DESIGN_SPEC_EXTRACT，原硬规则 19）

原型拍板后当场在浏览器跑 `extract-spec.js` 逐元素提取——显式 DOM 树（层级/顺序/父子）+ 布局语义（display/flex 方向/对齐/gap）+ 全量 computed styles（色/底/渐变/描边×4/圆角×4/阴影/字体/字距/内距/外距）+ 伪元素——落 `.taskflow/<id>/design/spec-extract.json` + `spec-extract.md` 结构树摘要。规格表是子任务 spec 的唯一视觉依据（附件引用，**禁止编排层凭记忆转述原型派发实现**）与验收对照物（程序采样逐项比对，抽查色值表不算对照）；原型 HTML 改动 = 重新提取。机械面：`validate-design-spec-gate.sh`（CHANGELOG 条目命中前端视觉资产 → 必含「规格表：」行指向有效 JSON 或「规格表：不适用——理由」）。

### 规则：样式真源门（STYLE_SOURCE_GATE，原硬规则 20）

项目初始化后 `docs/ui/style-source/`（prototype/ 定稿 HTML/CSS/JS + spec-*.json 规格表 + STYLE_DECISIONS.md 拍板日志）= 已定稿样式的**全局唯一真源**。两门：
1. **改真源文件** → 先用大白话呈报拍板——「现在长这样（截图）→ 要改成长这样（截图）→ 因为 X → 改不改？」——用户拍板后拍板记录追加 STYLE_DECISIONS.md + CHANGELOG 条目带「样式拍板：」行（或「语义中性——理由」），缺=收尾 `validate-style-source-gate.sh` 红灯；
2. **App 样式实现偏离规格表** → merge 阶段三产物一致性以真源规格表为准绳，未拍板的偏离=阻塞项。

**延迟加载**：项目未初始化真源时门降级通过，首个前端样式任务触点识别并引导安装 + 真源迁移；细则唯一载体 = 包内 `style-source.md`。

### 规则：双源机械输入，App 现状页是「长什么样」的唯一事实（APP_PAGE_BASELINE，原硬规则 21）

改现有页面的前端 UI 任务，原型立项时必须先机械提取现状基线——移动端跑 `extract-app-baseline.js`（device 模式 = 截图 + 结构树 + 可选静态 token 解析合并；static 模式 = 离线布局 XML→token 解析），web 用 `extract-spec.js` 指向**运行中的真实站点**——产物落 `.taskflow/<id>/design/baseline/`（**只住任务档案、不建全局基线库**；现状永远立项现提）。**原型 = 基线 + 显式 delta**：未改区域复刻基线（结构/顺序/token 值），禁止从零重画整页；已定稿原型/规格表 = 意图输入源，与现状冲突 = 呈报用户裁决。新增页面 = 「不适用——新增页面」+ 同类现状页取样。机械面：`validate-app-baseline-gate.sh`。

### 规则：渲染证据门（RENDER_EVIDENCE_GATE）

样式载体 diff 无任务档案 attachments 渲染证据（真实渲染截图+采样描述）= merge 锁拒；核心 `mergegate` 第三门同谓词。

### 规则：感知层验收（原硬规则 16②）

UI 行为类改动的验收项除数据断言外必须覆盖感知层：每个可达状态要么有解释载体（文案/提示行），要么 PRD 明确拍板「无解释」——测试断言解释载体的可见性与文案，不是只断言数据。

## 原型流程（PROTOTYPE_STALE：原型没有用户确认记录就往下做实现——流程直接拒绝）

原型六步链、交付迭代回路、prototype-selfcheck 自查表与术语化规范见包内文档（`prototype.md` / `prototype-selfcheck.md` / `style-source.md`，v3 从 references 迁入）；页面取证载体技能 = carrier 包 `page-forensics`。

## 事故档案（教训锚例，规则本体的证据）

- 2026-09-27 用户实证原型「像自己捏造的」→ 现状基线门（App 现状页唯一事实）的由来。
- 2026-09-27 用户拍板「系统的页面才是最新的，原型可作输入源」→ 双源结构。
- 2026-10-27 看板回退两次打回 → 「视觉变更判定不由模型自判」（删样式也算视觉变更）。
- 看板字体失调打回 → 渲染证据哨兵（样式 diff 必附真实渲染证据）。
