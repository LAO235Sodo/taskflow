# changelog-gates 包 — 收尾门族

> 能力包（v3.0.0）：任务收尾（CHANGELOG 条目）的机械门族。profile 缺省启用（`packs.changelog-gates=true`）。
> 安装产物：`node <skill目录>/scripts/tf.mjs mech install 决策组合门`（validate-changelog.sh + validate-decision-combo-gate.sh）。

## 规则全文

### 决策组合门 + 感知层验收（原硬规则 16）

① 凡改动命中 decisions/ 台账的代码资产（改动文件 basename 去扩展名 grep `.taskflow/decisions/*.md` 命中 **≥1 份决策文档**即触发——首次组合恰是风险最高点，无「≥2 任务」阈值），必须逐条评估「新改动 × 既有决策」组合后产生的**可达状态（含默认隐藏/折叠/抽屉态）**；组合产生新的不可解释状态（开放类：空/分叉/降级/隐藏/遮挡等）必须作为新增验收项呈报用户拍板，**单一决策声明「语义不变」不豁免组合检查**；留痕双通道：走任务=spec「决策组合评估」表（merge 阶段一脚本查完备性），任何改动=CHANGELOG 条目「组合评估：」行（列全量命中决策或「语义中性——理由」）。决策文档「影响范围」必须列文件/类名标识符，资产改名回写；「拍板无解释」类豁免决策也沉淀 decisions/。

② UI 行为类改动的验收项除数据断言外必须覆盖感知层（细则住 frontend 包「感知层验收」）。

### 同类排查门（CLASS_SWEEP_GATE，原硬规则 25）

任何缺陷确认点（用户打回 / 审查 blocker / 测试红）→ **动手修之前必答扩散三问**：
1. 上游——坏结果的输入/前提从哪来，它们干净吗；
2. 下游——这个缺陷的产物被谁消费了，消费方需要同步吗；
3. 同类——grep 同模式还有几处（缺陷先术语化成可 grep 特征）。

同类 >1 = 逐处修或逐处注记，「扩散面清单」落 findings.md；**修复 diff 必须附清单（merge.md 第 3 步修复循环核对，缺 = 阻塞项）**。与核心纪律「变更影响盘点」分工：彼是**变更触发**的写侧盘点（动手前列消费方），本是**发现触发**的读侧排查（修复前扫同类）；两个触发点都到时先盘点后排查。

机械面：`validate-changelog.sh`——修复类条目（触发词十三式：修复的 bug／修复 bug／修复了／缺陷修复／修复缺陷／修 bug／bug 修复／bugfix／bug-fix／fix(es)/fixed 带宾语搭配，大小写不敏感，含标题行）**条目块内**必含「同类排查：」行（N 处已修 / 唯一实例+证据）与「出现次数」，仅检锚点之上受管区（之下祖父豁免）。

### 文档同步门（DOC_SYNC_GATE，原硬规则 26）

① 写侧机械门：CHANGELOG 条目涉及文件命中功能代码（`__ASSET_EXTS__` 扩展名路径）→ 条目必含「文档同步：」行——列明本次更新了哪些 PRD/design/functional-map 条目；行为/契约确实零变更写「文档同步：不适用——理由」；缺行=收尾门红灯（延迟激活：锚点条目「文档同步门落地」未插入=未激活仅 WARN）。
② 读侧路由：功能边界类问答第一动作查项目统一源文档（路径由 conventions「统一源」节登记），以它为基准作答；未覆盖查代码并回写统一源——读侧反哺写侧。
