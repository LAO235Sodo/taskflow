# docs-prd 包 — 需求基线对照门

> 能力包（v3.0.0）：PRD/需求文档方向的门族。项目有 `docs/prd/` 且 profile 启用本包时加载；无 PRD 项目跳过（延迟激活）。
> 安装产物：`node <skill目录>/scripts/tf.mjs mech install REQ_ANCHOR_GATE`（基线门 + changelog 串接刷新）。

## 规则全文

### 需求基线对照门（BASELINE_GATE / REQ_ANCHOR_GATE，原硬规则 27）

1. **每条验收标准行尾挂 PRD 条目锚**（`基线：F-XX-NN / US-XX-NN`，只认条目 ID）；挂不上任何条目 = PRD 静默区 → 行尾写（`基线外：D-n`）并在 spec「基线外条目草案」节登记（口径原文/出处血缘/PRD 去向预填空号），**经用户确认后才动工**（拍板前禁按新口径动工——与需求变更门同语义）；草案收尾强制升格为 PRD 正式条目（含出处 iter-comment）或显式豁免拍板留痕。
2. **「见方案稿/原型/见上/待补」不是合法锚**（机械拒绝）；bugfix/工程工具类 AC 可显式豁免行（`基线：豁免——一句话理由`），**新增需求类行为禁豁免**。
3. **机械面** = `validate-baseline-anchor-gate.sh`（延迟激活：项目无 docs/prd/ 或 CHANGELOG 无「基线对照门落地」锚点=仅 WARN）——`--spec` 模式五检查（锚存在性/非法锚形态/草案升格/PRD 反向留痕/goalHash）挂 merge 阶段一，红=阻塞项；默认模式（文档同步行条目 ID 真实存在、引 PRD 路径须落条目粒度、触及 docs/prd/** 禁写不适用）由 validate-changelog.sh 收尾串接。
4. **与文档同步门分工**：DOC_SYNC 管「改了功能代码写没写文档」，本门管「写的/改的口径对不对得上需求基线」；门只证「链在」，「链对不对」仍归 merge 阶段一编排层语义核对。
5. **需求基线溯源（REQ_BASELINE）**：spec 必须写清需求出自哪份 PRD 文档哪条，防止需求来源失传；新任务 spec「需求基线」节 + doctor I12 对账。

## 事故档案

- 2026-10-18 拍板：任务列表行显示口径拍板后 19 天才被发现偏离基线，六道相邻门全放行——每道门都查「有锚的链对不对」，没有一道门强制「每条行为口径必须有锚」。
