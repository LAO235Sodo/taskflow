# 经验归纳（被批评后长记性）

> 用户纠正流程错误时触发（SKILL.md 意图识别表路由至此）。机制借鉴 superdx `experience-induction`，持久化目标改为**本技能规则文件 + 项目侧规矩**（非 auto-memory）——归纳是对规则的修改，规则是高影响资产，落地必须过确认。

## 触发信号（检测到即触发，不等用户点名「记一条规矩」）

| 类别 | 典型表达 |
| --- | --- |
| 流程违规 | "流程不对"、"这个阶段应该…"、"跳过了确认步骤"、"直接在主仓库改了" |
| 产出不合格 | "呈报不合格"、"看不懂"、"太长了抓不住重点"、"纯文字没法判断" |
| 质量不足 | "这审查太表面"、"测试没过就说完成"、"结论没落档" |
| 状态异常 | "档案和实际进度对不上"、"恢复后跳了步骤" |

## 归纳步骤

1. **检测信号**：从用户反馈识别类别；语义含糊（"不对"但没说哪不对）→ 先问清楚再归纳，不猜。
2. **提取错误模式**：把具体事件抽象为通用规则——本次错在哪、下次同场景该怎么判。一句纠正归纳一条规则，不上纲上线也不缩小。
3. **查重合并（MUST）**：落笔前先翻既有条目——本技能 `CHANGELOG.md`、`SKILL.md` 硬规则、`references/*`、项目 `conventions.md` 与根 `AGENTS.md`——语义相近的**合并扩展**（把新场景写进既有规则的 How to apply），不新增重复条目。实测反面：同一教训散改四处（AGENTS.md/conventions/CHANGELOG/硬规则），下轮盘点被判噪音。
4. **编码规则**：结构 = **规则一句 + Why（哪次实证逼出来的，带日期/任务短码锚点）+ How to apply（落到哪个文件哪个触点）**。没有 Why 的规则会在下轮盘点被当噪音清掉。
5. **呈报确认**：向用户展示提炼出的规则原文，确认后才落笔——静默改规则 = 编排层替用户立规矩，越权。
6. **双落点持久化（用户拍板 2026-09-22）**：
   - 本技能 → `CHANGELOG.md` 新版本节（版本号按变更量定，写法照抄本文件结构）
   - 跨项目红线 → 项目根 `AGENTS.md` 红线摘要 / `conventions.md` 对应小节同步镜像——保证每个新会话一开口就看得见，不等再犯一次
   - **产出不合格类（「看不懂」/呈报打回）→ 词表回路**：归纳同时把涉及的新行话登记 `references/glossary.md`（行话+大白话+锚词）——PLAIN_SPEECH_GATE 词表由此生长，每次反馈都在收紧机器检测面，同类反馈第二次发生=词表漏登；**已登记词条白话仍看不懂 → 改写该词条（白话+锚词一起换到用户能理解的风格），禁另开同词条**（2026-10-09 拍板）
7. **代码不因此免检**：规则修的是流程；流程出错造成的烂摊子（错误提交、误删、未落档）仍按对应流程修复——归纳不替代清理。

## 反面模式

- **攒批不归纳**：同一类纠正第二次发生 = 第一次归纳失败（没落地或没查重），先复盘再归纳。
- **只改一处**：SKILL.md 改了、references 触点没接线 = 规则够不着（可视化硬规则实证：住在 domain.md，普通 resume 路径根本不经过）；双落点同理，镜像缺失 = 白记。
- **规则没有触点**：归纳完必须回答"下次哪个动作会读到它"——答不出的规则是死文字，改到触点上或并进既有条目。

## 新功能 DoD（把上面的纪律提前到加功能时，不止被批评后）

给本技能新增任何机制/不变量/命令/门，**同一个变更**里必须交付（缺一 = lint/doctor --self/测试红灯，不是靠 review 记性）：

1. **事实落注册处**：不变量 → data.md「不变量」表 + tf.mjs `INVARIANTS`；机制 → data.md「机制登记表」；状态变化 → data.md「状态机」表（撤销路径列必填）；命令 → tf.mjs 分发区 + USAGE。
2. **触点 ≥1 且 lint 可验证**：机制 token 字面写进触点文件（流程文件的对应步骤），机制登记表登记该触点。
3. **对应机械检查**：能下沉 lint/doctor 的必须下沉，并配 fixture 用例（先红后绿——先在旧代码上跑红再实现）。
4. **prose 零复述**：计数/范围/清单只指真相源（data.md 表 / 分发区 / templates/ 目录），lint 事实禁改写清单把关。
5. **门禁行更新**：conventions.md「验证清单」纳入新检查——检查器自身也要有触点，否则它是下一个死规则。
