# 问答管线（提问类输入：理解回显 → 定向探索 → 带证作答 → 追问衔接）

> 触发：SKILL.md 意图路由「问代码/领域问题」行（求解释/现状/位置/可复用性，非改动描述、非任务进度）。**判定动作外显**：`识别为〈问答〉——〈依据〉`。答案文风走 PLAIN_SPEECH_GATE（细则 packs/briefing/plain-speech.md）。机制：**理解先外显、先纠正、指代落地**；禁跳过管线自己搜代码直接作答，禁静默选定一种解读边搜边脑补（产出后锚定，事后纠正更贵）。

## 第 1 段：理解回显（先于探索，禁先搜后答再补理解）

**答案的第一句话必须是理解回显**：`你问的是〈X〉，我指向〈对象/范围〉，按〈口径〉作答。` 多义 → 列候选口径请用户选 / 纯查询分口径并列；回显被纠正 → 按新口径走第 2 段，不辩解不锚定原解读。

- **口径层判定（功能/页面类问答必过）**：「怎么填充/怎么用/什么效果」类动词先辨两层——**数据口径**（选项来源/字段落库/契约链路）vs **交互行为口径**（操作→状态变化→退出重进等生命周期）。交互口径优先或双口径并列请用户选，**禁默认只答数据链路**——话语命中实现词汇 ≠ 用户诉求在实现层。
- **意图档位判定（认知对齐优先，方案悬置）**：探索前先辨用户在**对照认知**还是**发起改动**。理解型信号（「怎么实现的/为什么这样/和我理解的一样吗」）→ 回答止于：实际实现呈现（代码锚+链路，按证据源分级）+ **与用户认知的差异点主动对照**；**禁主动附方案/改动建议/多方案并列呈报**——对齐后唯一合法收口 = 确认问句（「实现与你的理解一致吗？要调整的话我们再立项。」）；功能面取舍的方案内拍板仅适用已立项任务。
- **豁免档（类型制）**：仅「定义/位置/指针类」（答案=纯文件:行号指向、零行为断言）可豁免——回显压缩成答案首行。凡含「有没有/会不会/支不支持」类**行为断言**一律不豁免，一行能答也须走完整管线（一行答出的是推断）。

## 第 2 段：定向探索（按问题卡探索，不漫搜）

先答三问再搜（**第 0 问 = 口径层判定**——口径层选错则探索方向全错）：搜什么（符号/字段/路由/报错文案）｜在哪搜（目录/文件线索/领域词）｜什么算答对（判定标准）。

- 渲染事实采样定案不目测；答案涉语义行为先盘消费方，不凭单点代码下「全链生效」结论；技能联动按 domain.md「问答」行加载。
- **功能边界类统一源路由**：命中边界特征词（能不能/谁可以/什么权限/边界/在哪）→ 先查**项目统一源**（conventions.md「统一源」节登记，未登记跳过直查代码），以它为答案基准；未覆盖再查代码并**回写统一源**；冲突 → 代码为准、回写修正。
- 引用了 PRD 条目编号 → 顺手 grep `docs/prd/**` 确认条目存在（防幽灵条目）；查无 → 如实注记并列最接近条目，不猜号。

## 第 3 段：带证作答

结构固定：**结论一句话 → 主体（先骨架后血肉）→ 不确定性与边界 → 证据自检行**。

- **证据自检行**：答案尾部固定一行——`证据构成：代码实证 N 处（文件:行号）｜实测 M 项｜文档 D 项（来源：URL/prd 条目）｜推断 K 项（未验证）`；全实证写「无推断」。所列锚必须是正文实际引用且支撑对应结论的锚，装饰性列举按虚报论（豁免档除外，缺失可打回）。
- **证据源分级**：**强度序**：运行时实测 > 代码实证 > 统一源文档 > 链式推断；行为/现状类回答必须基于可用最高强度源，**代码可查的问题禁用推断作答**。**一跳一实证**：链式推理每一跳独立查证（「权限服务放行」≠「UI 上有入口」）。**实证/推断分标**：未验证项显式标注，禁混排成同一确信度。**实测优先**：用户观察与结论冲突 → 立即重查修正，禁辩护旧答案；仍冲突 → 呈两造证据请用户复核操作路径——禁坚持旧结论，也禁无实证顺从改写。
- **外部事实断言**（第三方系统行为/配置规则/API 语义）：**官方文档原文或本人实测复现，附来源 URL——查证在作答前完成**；凭「文档记忆/社区经验」给确定性结论 = 红线；查证成本过高的显式标「推断，建议验证」+ 附验证方法，禁「必须/一定/不可能」措辞。自检一句话：错了谁担责？——担责的断言必须带信源。
- **主体骨架**：单点事实 → 短段落一段一中心；≥2 并列场景/条件 → 先编号清单或矩阵表格给全貌，再逐格 1–3 句叙事展开，多维真相禁埋进段落流让读者拼装；证据落痕（文件:行号）跟在各结论格后。无证据的结论标「推测」不定论语气；行话首现带大白话、代号禁裸奔。

## 第 4 段：追问衔接（问答不是孤岛）

| 追问信号 | 衔接节点 |
| --- | --- |
| 「那怎么改 / 能不能复用到 X」 | 反馈分类 → 新需求走需求溯源 + 归入 vs 另开判定 |
| 探索中发现疑似 bug | 只报告不动手（问答不改码）；修复走新任务，建档先 `tf.mjs scout <症状词>` 判 🔁回归/🆕首次 |
| 回答被打回（答非所问/没理解我） | 经验归纳（induction.md）：先复盘是回显缺失还是口径选错，再归纳 |
| 问题实为需求描述 | 不硬套管线，转「新任务」——管线服务理解，不绑架意图 |
| 机制类追问（「为什么拦我/XX 编号是什么」） | 按 `node tf.mjs mechanisms` 门清单与 mechanisms.json `plain` 大白话解释当前生效的门与触发原因——代号首现带括号白话，禁裸代号回答 |
