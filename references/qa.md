# 问答管线（提问类输入：回显理解 → 定向探索 → 带证作答 → 追问衔接）

> 触发：SKILL.md 意图识别表「问代码/领域问题」行（求解释/现状/位置/可复用性，非改动描述、非任务进度）。硬规则 15 的细则载体。**判定动作外显**：`识别为〈问答〉——〈依据〉`。答案的叙事体与结构化双层要求统一走 PLAIN_SPEECH_GATE（硬规则 24，细则 references/plain-speech.md——本文件的骨架规范是其问答实例）。

## 为什么问答要走管线（反面实证）

提问类输入曾有两条死路：

- **不触发**：触发词无「提问」→ taskflow 不加载 → 编排层裸奔：自己搜代码直接作答。理解过程黑盒，用户无法分辨「模型没理解我」还是「代码本来如此」。
- **边搜边脑补**：静默选定一种解读 → 搜索与回答全部建立在这个解读上 → 产出后锚定，事后纠正要对抗锚点，比事前对齐贵。

用户实证（2026-09-26）：增量问答（先问「做了什么」再问「怎么改/能不能复用」）反而更准——机制 = **理解先外显、先纠正、指代落地**（「这里」从猜测变成双方都看过的具体代码）。本管线把该机制从第二轮前移到首次回答。

## 第 1 段：理解回显门（CRITICAL——回显先于探索，禁止先搜后答再补理解）

**答案的第一句话必须是理解回显，不是探索结果**：

> 你问的是〈X〉，我指向〈对象/范围〉，按〈口径〉作答。

- 回显里任何一处多义 → 硬规则 10（列候选口径请用户选 / 纯查询分口径并列作答）
- **口径层判定（功能/页面类问答必过，2026-09-30 枚举字段问答实证并入）**：功能/页面类问答（「XX 怎么填充/怎么工作/怎么用/什么效果」）的「口径」必须先辨两层——**数据口径**（选项来源/字段落库/契约链路）vs **交互行为口径**（用户操作→状态变化→退出重进等生命周期）。凡指向产品功能的「怎么填充/怎么用」类动词，交互口径优先作答或双口径并列请用户选，**禁止默认只答数据链路**——话语命中实现词汇 ≠ 用户诉求在实现层（实证：问「分类怎么填充」，按数据口径答了字典端点+落库，用户真实诉求是「选了没传退出会怎样」，多走两轮才命中；兜底依硬规则 10「判不清按多义」）
- **豁免档**：一行能答的琐碎问题（「X 定义在哪」）不设阻塞——回显压缩成答案首行（「你问的是 X——在〈文件:行号〉」），错了用户自然会纠正
- 回显被纠正 → 按纠正后的口径走第 2 段，不辩解不锚定原解读

## 第 2 段：定向探索（按问题卡探索，不漫搜）

探索前先答三问，答不出就先补齐再搜（**第 0 问 = 第 1 段口径层判定**——功能/页面类问题先定数据/交互口径层，口径层选错则探索方向全错）：

| 三问 | 内容 |
| --- | --- |
| 搜什么 | 符号 / 字段 / 路由 / 报错文案（标准术语，硬规则 12） |
| 在哪搜 | 目录 / 文件线索 / 命中信号的领域词 |
| 什么算答对 | 判定标准（找到什么才算回答了用户的问题） |

- 技能联动：按 domain.md 生命周期阶段表「问答」行加载（代码导航 / 外部调研 / 需求溯源各有正主）
- 硬规则 13/14 照常适用：渲染事实采样定案，不目测定案；答案涉语义行为先盘消费方，不凭单点代码下「全链生效」结论

**功能边界类问答的统一源路由（DOC_SYNC_GATE 读侧，硬规则 26；2026-10-10 拍板）**：问题命中功能边界特征词（能不能 / 谁可以 / 什么状态 / 什么权限 / 边界 / 功能在哪）→ 第一步查**项目统一源文档**（路径由项目 conventions.md「统一源」节登记，未登记则跳过本路由直接走代码探索），以它为答案基准作答；统一源未覆盖的再查代码，并**把查到的边界回写统一源**（读侧反哺写侧——地图越用越全）；统一源与代码冲突时按「数据类问题以运行中服务为唯一事实源」既有铁律处理（代码为准、回写修正统一源）。防的病：每个边界问题都现场翻代码（没有一处查全部的地图）+ 功能改了文档没人强制跟着改（写侧门治本、本路由治标引流）。

**口径类问答的条目锚核对（REQ_ANCHOR_GATE，可选增量——非本门承重）**：作答引用了 PRD 条目编号（如 F-XX-NN / US-XX-NN）→ 顺手 grep `docs/prd/**` 确认条目标题真实存在（防读侧引用幽灵条目，误导后续 spec 挂锚——REQ_ANCHOR_GATE 的锚存在性检查会拦，但读侧先核省一轮返工）；条目不存在 → 如实注记「查无此条目」并列最接近条目，不猜号。

## 第 3 段：带证作答

结构固定：**结论一句话 → 主体（按答案形态选骨架）→ 不确定性与边界**。

**主体骨架（2026-09-30 实证扩展：首尾三段式只管结论与边界，主体无规范则场景一多退化成段落流）**：

- 单点事实/机制解释 → 短段落，一段一个中心。
- **≥2 个并列场景/分支/条件 → 先骨架后血肉**：先用编号清单或矩阵表格（场景 × 条件 → 结果）给出全貌，再逐格用 1–3 句叙事展开；多维组合真相**禁止埋进段落流让读者自行拼装**（实证：三场景×两路径=6 格真相用叙事承载，用户判「内容很乱、逻辑不清晰」；同会话同类内容改用表格后清晰度立判——病灶在主体骨架缺失，非叙事体本身）。
- 存在对比维度（如「两种退出路径」）→ 优先矩阵表格。
- 证据落痕（文件:行号）跟在各结论格之后作锚点——不混在长句中间切碎句子，不集中堆文末。
- 与项目「叙事体、表格仅限数据对比」拍板兼容：矩阵/清单做骨架（结构），格子内叙事解释（血肉）——多场景×多条件对比正是「真正的数据对比」。
- 双层要求统一载体：血肉层（叙事句子、术语首现带大白话括号、代号禁裸奔）与骨架层选型表见 references/plain-speech.md（PLAIN_SPEECH_GATE，硬规则 24）。

- 证据 = 文件:行号 + 关键代码/数据摘录；**无证据的结论必须标注「推测」**（硬规则 15），推测不得写成定论语气
- 表述精确但用人话：现象 + 根因 + 依据的因果链必须完整（硬规则 12 精神——禁「那个地方有点乱」式含糊），同时行话首现带大白话、句式叙事化（PLAIN_SPEECH_GATE 血肉层）

## 第 4 段：追问衔接（与既有节点握手，问答不是孤岛）

| 追问信号 | 衔接节点 |
| --- | --- |
| 「那怎么改 / 能不能复用到 X」 | SKILL.md 反馈分类 → 新需求走 PRD 溯源门（无文档先补/呈用户决定）+ 归入 vs 另开判定 |
| 探索中发现疑似 bug | 只报告不动手（问答不改码）；修复走新任务，判性质按 🔁 回归纪律 |
| 回答被打回（答非所问/没理解我） | 经验归纳（induction.md）：先复盘是回显缺失还是口径选错，再归纳 |
| 问题实为需求描述（用户开口就是要改） | 不硬套管线，转「新任务」/反馈分类——管线服务理解，不绑架意图 |
