# merge（合并）——顺序不可调换、步骤不可跳过

> 面向大量并行任务的说明：归档时 managed 任务的 worktree 自动移除（第 12 步），无需询问。

1. 先做一次 checkpoint（checkpoint.md）——保证审的是已存档状态。
2. 进入任务 worktree（anchor=attached 任务在主仓库当前分支执行），确认主分支名（main / master，有疑问问用户）。
3. **同步主分支**（保证审的是最新代码，避免覆盖他人新改动）：

```bash
git merge main    # 在任务分支上执行；冲突当场解决，只能改文件，禁止任何丢弃式操作
```

4. **验收**：运行 spec.md 中的验收命令；spec 未定义则问用户。验收不过 → 修复后回到本步。
5. **强制审查（不可跳）**：生成 `git diff <主分支>...<任务分支>` 全量 diff，按两阶段清单审查：
   - **medium / large**：派**全新上下文的子代理**审查（只读用 explore，需要跑验证用 general），交付物：diff 全文 + spec.md + 清单。
   - **small：编排层自查**——亲自读全量 diff，按同一份清单自查，并亲自跑验收命令；**不派子代理**。
   - **阶段一 spec 合规**：验收标准逐条核对；有无漏做、多做、做偏。
   - **阶段二 代码质量**：错误处理、边界条件、安全隐患、是否破坏既有行为、与周边代码风格一致性。
   - 审查输出必须分：**阻塞项**（必须修）/ **建议项**（可选）。
   - 领域专项：按 references/domain.md 追加——UI → `web-design-guidelines`；API → `api-design-principles`；后端各栈 → 对应栈技能；测试代码 → 对应 testing 技能。专项阻塞项同样必须修复。
6. 有阻塞项 → 回任务分支修复 → 重新执行第 5 步（循环直到无阻塞）。
7. 无阻塞 → 把审查结论与风险点呈现给用户，**等用户明确确认**。
8. 用户确认后合并，**并立即切换状态**：

```bash
cd <主仓库根> && git merge --no-ff <任务分支>
# task.json 与 index.json：status → verifying（git 已合并，验收闭环开始）
```

9. **推送与部署（按项目约定 conventions.md）**：
   - 读 `.opencode/tasks/conventions.md` 的「推送与部署」「验证清单」「完成定义」三节；不存在 → 引导问答生成（怎么部署？部署后逐项验证什么？什么算最终完成？）。生成后跨任务复用。
   - 有 remote → 按约定 push 主分支（未约定时问一次）。
   - 按约定执行部署 + 验证清单**逐项过**，每项记录结果。
   - **执行远程部署命令之前，先向用户展示完整命令清单并获确认**（高影响动作）。

10. **用户最终验收（归档的前置条件）**：呈现部署与验证结果 → 用户明确确认通过 → 才允许归档。
    - 任一环节失败或用户不认可 → **停在当前环节、保持 `verifying`，不归档**；修复/重部署后回到本步。中断后恢复（resume.md 第 9 步）直接从本步续。

11. **决策沉淀**：decisions.md 中项目级重要条目 → 每条写一份 `.opencode/tasks/decisions/YYYY-MM-DD-<slug>.md`（背景 / 决策 / 被否决方案及原因 / 影响范围）。这一步不可省——任务会结束，决策留在项目。注意：部署/验收类约定只更新 conventions.md，不重复写入决策库。
12. **归档**：task.json 与 index.json 标 `status=merged` + 时间戳，按 anchor 区分清理：
    - `managed`：**自动移除任务 worktree**（`git worktree remove ../<dir>`，不询问——merge/验收/归档全通过后它已无价值，并行任务多时不留垃圾目录）；分支**保留**（`git branch -d`，**禁用 -D**）作追溯。若 git 拒绝移除（worktree 有未提交/未跟踪文件）→ **禁用 --force**，报告原因交用户处理。
    - `attached`：**绝不自动删除用户的分支或外部 worktree**（那是用户/其他工具的资产）；只归档任务文档，清理必须询问且默认不做。
13. 汇报：合并结果、部署验证结果、沉淀了哪些决策、清理情况。

**并行子任务的合并**（split.md 产生的）：按同样顺序把 `task/<id>/<n>-<slug>` 合回 `task/<id>`（同步对象改为任务分支），子任务 worktree 合并完成后**自动移除**（同上规则：git 拒绝则报告原因，不 force）；全部子任务归档后再走本节任务级 merge。
