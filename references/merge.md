# merge（合并）——两条命名路径，共享节点显式标注

> **路径由 conventions.md 的合并时序决定**（第 2 步读一次，全程缓存，不重复读）：
> - **merge-first（默认，无约定时）**：走完 1-4 后合并（5）→ 部署（6）→ 验收（7）→ 归档（8）
> - **verify-first（约定"先部署测试环境 → 用户验收通过 → 再合并"）**：走完 1-4 后先 6（部署，`--deployed` 翻 verifying）→ 7（验收）→ 用户"验收通过" → 回 5 合并 → `accept <id> --pass` 翻 merged → 直接 8 归档（与 merge-first 共用同一状态机，见 data.md「状态机」；区别仅 verifying 悬置更短——v2.21.0 勘误：原「无 verifying」措辞与 --deployed 机械翻转自相矛盾）
>
> 步骤编号是阅读顺序，控制流按上述路径走；不存在"绝对不可调换"，也不允许跳过任何闸门。

1. **预检与同步**：先做一次 checkpoint（见 checkpoint.md 触发点；该存档覆盖至第 3 步审查派发，其间产生新改动先补轻量存档）。**会话工作台**：本八步流程 init 成 omp Todo（部署/验收常跨天，防漏步——SKILL.md「会话工作台」）。进入任务 worktree（anchor=attached 任务在主仓库当前分支执行）；确认主分支名（`git symbolic-ref refs/remotes/origin/HEAD` 可探测，有疑问问用户），然后同步基线：**同步后重跑决策组合门脚本（`validate-decision-combo-gate.sh --spec <spec> --base <main>`）**——并行任务在同步窗口内新合入的决策文档也会被扫到（B5 并行在途覆盖；新命中 = 回 spec 补组合评估表再进审查）。

   ```bash
   git merge <main>    # 在任务分支上执行；冲突当场解决，只能改文件，禁止任何丢弃式操作
   ```

   冲突复杂/多文件纠缠时联动 `resolving-merge-conflicts` 技能按依赖分析逐个解（domain.md 阶段轴），不裸拼。

  冲突分级：机械冲突（imports/格式化）当场解；语义冲突（判据=冲突块双方改动行均非空且属同一语法单元/逻辑块）→ 逐处呈报「A 侧意图/B 侧意图/合并建议」经用户拍板后落笔；分级由 conflict-triage 技能引导（机械/语义冲突形态清单+灰区默认升语义+三行呈报模板），缺失按硬规则 22 检测呈选装——硬规则 1 拦破坏性操作，拦不住静默选错边（并行任务 main 侧限流参数被任务分支静默覆盖=行为回归，越界门/stale/快照门均不覆盖语义丢弃）。

2. **读约定（一次）**：读 conventions.md 的「推送与部署」「验证清单」「完成定义」+ 合并时序，判定走 merge-first 还是 verify-first，**全程缓存不再重复读**。文件不存在 → **停止并报告**，回 new-task.md 初始化流程补建后再来（不在 merge 中途发起问答访谈——那会把已完成的任务卡在半空）。纯本地/无部署需求 → 部署相关节 N/A。
3. **审查（不可跳；唯一修复循环）**：生成 diff 基线 `git diff <main>...<任务分支>`，按两阶段清单审查：
   - **small**：编排层自查——亲自读全量 diff + 亲自跑 spec 验收命令，不派子代理。
   - **medium / large**：派全新上下文的子代理（只读用 explore，需跑验证用 general）。**交付物 = commit 范围 + 文件清单 + spec.md 路径**——子代理有仓库访问权，自行 `git diff` 拿全文，编排层**不得把 diff 全文塞进派发提示**（双倍 token）；diff 过大（粗略阈值：>2 万行）按目录分片多次派发，结论汇总。
   - **审查范围与建议分级**（2026-09-22 用户拍板收窄）：只对**语义承载文件**派审（SKILL.md 硬规则/意图表、registry、domain.md 映射、tf.mjs、spec/conventions 模板）；叶子改动（CHANGELOG、注释、单文件措辞）编排层自查免审。派审前编排层先过**接线自查清单**（新条目有映射？新小节有路由？新信号有分支？新门有 checklist 项？）。审查建议**分级处理**：真缺口（路由没接/语义打架/门可绕过）当轮修；措辞级记 findings 留下轮——不为凑数全修。可静态化的检查逐步下沉 lint（真值趋零则审查再收窄，数据裁决）。
   - **阶段一 spec+PRD 合规**：验收标准逐条核对 + 执行 spec 中的验收命令；有无漏做、多做、做偏。**三链核对（REQ_BASELINE）升格双层（REQ_ANCHOR_GATE，硬规则 27）**：**第一层机械——跑项目 `validate-baseline-anchor-gate.sh --spec <spec.md> [--base <main>] [--repo <检出路径>]` 五检查**（`--repo`（v2.77.2）：worktree 任务必传任务 worktree 路径——缺省恒主仓库检出会使 `git diff main...HEAD` 恒空、B3 草案升格必红（2026-10-24 dept-unread-window 实证）；簿记 conventions/task.json 仍自动定位主仓库，无需关心。五检查：B1 锚存在性：每条验收标准须挂 PRD 条目 ID 或「基线外：D-n」草案锚；B2 非法锚形态；B3 草案升格；B4 PRD 反向留痕；B5 goalHash），任一红 = 阻塞项按下方分流表走回路；**第二层语义——实现 ↔ spec 验收项 ↔ 需求基线节所链 PRD 条目逐条对得上**（脚本只证「链在」，「链对不对」归编排层，脚本绿不豁免本核对），断链 = 阻塞项；spec 承重节 hash 与 task.json goalHash 不符 = 未经需求变更门的改动（与 doctor I11 同源）→ 回变更门补 `tf.mjs req-confirm` 或回退。pre-v2.23 档案无基线节 → 跳过三链核对并 ℹ 注记。**门红分流表（门只供弹不改回路——全部回流本步唯一修复循环）**：
     | 门红检查 | 红因 | 分流 |
     | --- | --- | --- |
     | B1 锚存在性 | 验收项挂不上 PRD 条目 = 静默区行为 | 草案登记（spec「基线外条目草案」节，口径原文/出处血缘/PRD 去向预填空号）+ 并入方案稿/质询轮呈报确认 → spec 更新 → `req-confirm` 落痕 → 重跑门 |
     | B2 非法锚形态 | 锚写「见方案稿/原型/见上/待补」 | 改挂真条目 ID；确实无条目可挂走 B1 草案路径 |
     | B3 草案未升格 | diff 无预填条目 ID | 二选一：补 PRD 正式条目（含出处 iter-comment）/ 用户拍板豁免留痕 |
     | B4 PRD 反向无留痕 | PRD 条目被改且四路（spec 锚/草案去向/文档同步行/reqChanges）皆无 | 需求变更门呈报（原口径引文→新口径→影响一行）→ 拍板 → PRD+spec 同步改 + `req-confirm` → 重跑门 |
     | B5 goalHash 失配 | spec 承重节被改未经 req-confirm | 同既有 I11 处置（补确认或回退）——I11 红跑 req-confirm 补确认前，先核对拍板证据（对话中用户原话/时刻，引述进 --note）；无证据唯一处置=回退 spec，禁补确认（防违规者自编拍板记录把门变橡皮图章） |
     | 同一阻塞第 3 轮 | 修复打转 | STUCK 升级门（本文件第 3 步尾部） |
   - **决策组合门完备性（硬规则 16①，机械化）**：跑项目 `validate-decision-combo-gate.sh --spec <spec.md> --base <main>`——分支 diff 命中的决策文档必须全部出现在 spec「决策组合评估」表（查「全不全」不只查「有没有」），缺 = 阻塞项回 spec 补。
   - **找茬注记核对（v2.53.0）**：spec 关键决策节含三类高危命中（跨模块/编译器验不了的属性/不可逆）但「找茬注记」表空白或纯否定词（「暂未发现/无/已覆盖」）→ 阻塞项——回质询补三答（与 new-task 第 11 步派发核对双设）。
   - **阶段二 代码质量**：错误处理、边界条件、安全隐患、是否破坏既有行为、与周边代码风格一致性。**审查三轴（硬规则 25 C 面，任何审查者必做——2026-10-09 审查者自发行为固化）**：①**上下游**——diff 改动的每个输入来源/输出去向逐项点名（谁喂数据、谁消费结果，漏点名 = 审查不完整）；②**同类**——diff 内每个新守卫/新分支/新范式，问「同类还有吗」grep 比对并把结论写进审查报告（反面实证：F/G 任务兄弟 worktree 死路 + F 缺 `!dir` 守卫两个 blocker 都靠审查者自发同类比对才抓到）；③**组合**——新改动 × 既有决策/机制交互（决策组合门硬规则 16① 承接，此处核对执行）。**决策组合门（硬规则 16①）**：核对阶段一脚本输出——组合评估表命中的每份决策是否真的被评估过（防橡皮图章：表在但内容空洞 = 阻塞），组合新可达状态（含默认隐藏/折叠/抽屉态）是否都转成了验收项。**感知层验收（硬规则 16②）**：验收项覆盖不可解释状态（开放类：空/分叉/降级/隐藏/遮挡等）的解释载体断言，不是只断言数据。**测试先行动证（代码任务）**：抽查核心测试文件与被测实现的首次提交先后（`git log --diff-filter=A --format='%ci %s' -- <文件>` 两相对比）——测试晚于实现且无解释（hotfix/存量补挂可豁免）→ 建议项记 findings（后写测试天然迁就实现，TDD 防幻觉对齐失效）。**测试强制矩阵核对（testing.md §九）**：按变更类型过四项——bug_fix 无回归测试先红 = 阻塞；refactor 无开工前全绿基线 = 阻塞；数据迁移未过四断言 = 阻塞（TDD_VIOLATION）；文档同步缺失 = 门控失败。**同类排查核对（CLASS_SWEEP_GATE，硬规则 25）**：本任务若有缺陷确认点（打回/blocker/测试红），修复 diff 必须附扩散面清单（testing.md §十）——缺 = 阻塞项。
   - **文档同步行自答（DOC_SYNC_GATE，硬规则 26 写侧）**：本次收尾 CHANGELOG 条目涉及功能代码 → 逐条目预答「文档同步：」行（更新了哪些 PRD/design/functional-map 条目，或「不适用——理由」）——validate-changelog.sh 收尾必查，本步自答免收尾红灯返工。
   - **值域归属核对（domain.md「前后端职责判定」表 + 判别问句）**：diff 新增前端硬编码可变选项集（业务枚举数组/映射常量进 bundle）——spec 有值域归属拍板或静态固化权衡注记 = 过；无注记 = 阻塞项（改走后端字典端点，或补权衡理由走需求变更门）；后端以常量/枚举类承载值域同步核对（非目标形态，判别见 domain.md）。
   - **阶段三 产物一致性（前端 UI/large）**：前端判定按 domain.md 信号表对 diff 文件扩展名/需求词复核（旧档案无标注时同法）。用户故事 ↔ 原型 ↔ 实现 ↔ 验收标准逐条核对——状态名/字段名/按钮文案等语义措辞**逐字比对**（实证：复核三态「确认不合格」被原型渲染成「已确认合格」，语义反向只有逐字比对才抓得住）；原型无用户确认记录 → **PROTOTYPE_STALE 门禁拒绝**（与 new-task.md 第 11 步双设）；**前端视觉验收对照物 = DESIGN_SPEC_EXTRACT 规格表（prototype-selfcheck.md 标准来源首位；项目已初始化样式真源 docs/ui/style-source/ → 以真源规格表为准绳，未拍板的样式偏离=阻塞，STYLE_SOURCE_GATE 硬规则 20——细则 references/style-source.md）——实现渲染采样值 vs 规格表逐项比对，抽查色值表不算对照；跑 `validate-design-spec-gate.sh --spec <spec.md>` 复核挂链**。**pre-2.16.0 旧档案无产物链节**：允许补记原型确认时间/会话后放行；无记录且无法补证 → 回唯一修复循环请用户补确认。
   - **阶段三追加（APP_PAGE_BASELINE，硬规则 21——改现有页面任务）**：产物链「现状基线」行复核——跑项目 `validate-app-baseline-gate.sh --spec <spec.md>`（已拍板原型 → 基线行必须在链且 schema 有效——app-baseline/1（Android）/ design-spec-extract/1（web）——或「不适用——理由」）；**原型 ↔ 现状基线对照**：未改区域逐项比对基线（结构/顺序/token 值），基线↔真源规格表分歧 = 呈报用户裁决（App 未留痕漂移 → 补 STYLE_SOURCE_GATE 门一拍板；原型过时 → 真源回写/重提取），禁止静默取舍；项目未装该门（无脚本/无锚点）且任务属改现有页 → 呈报一次安装建议（`node tf.mjs mech install APP_PAGE_BASELINE`，延迟初始化——与 new-task 第 8 步同模式）。
   - 输出必须分：**阻塞项**（必须修）/ **建议项**（可选）。领域专项按 references/domain.md 追加（UI/API/后端栈/测试），专项阻塞项同样必须修复。
   - **任一阶段不过 → 先答扩散三问（CLASS_SWEEP_GATE，硬规则 25：上游/下游/同类 grep，扩散面清单落 findings）→ 修复（diff 附清单，缺 = 阻塞项）→ 重跑本步**（本流程只有这一个修复循环，验收失败与审查阻塞同走此处）。**STUCK升级门：同一阻塞项第 3 次修复仍不过，或同一 spec 连续 3 轮修复均产生新阻塞项（打转趋势——每轮症状不同但方案级错误未变，按表象计数可绕：时区缺陷逐轮修格式化/存取/展示，全链时区策略错误永不升级），任一命中即升级 → 禁止第 4 轮默默重试**——呈报「卡点 + 已修轮数 + 每轮各改了什么」，三选一请用户拍板：换实现方案 / 收窄或重写验收标准（spec 增补流程） / revert 回退（data.md 状态机撤销路径）。
4. 无阻塞 → **呈报用户一次**：审查结论 + 风险点 + 验收结果 + 后续安排（合并→部署→验收 或 verify-first 顺序）+ **managed 任务归档时将自动移除任务 worktree（分支保留，`-d` 不 `-D`）** → 等用户明确确认。**呈报稿先落 `.taskflow/<id>/briefing-审查呈报.md` 过 PLAIN_SPEECH_GATE 门（硬规则 24——行话带大白话、代号带括号、句子拆短，红=重写绿才呈报）**。**large 档固化验收结论**：呈报同时把「逐验收项判定 + 阻塞项清零确认 + **明确放弃项及理由**」写入 spec.md「验收结论」节（templates/spec.md 占位）——范围收窄必须显式落痕，禁止口头（实证：brand-miss 判卷尾巴「砍不砍」悬置无落点=验收范围漂移）。**前端 UI/large 任务呈报必须附评审包四件套路径**（用户故事/PRD、原型、决策表、验收标准——spec「产物链」节现成），评审按旅程走查不按页走查。
   **快照拍档（MERGE_GATE 门一数据源，v2.58.0）**：审查呈报落稿后立即跑 `node <skill目录>/scripts/tf.mjs snapshot <task-id>`（main HEAD 哈希写入 task.json.mergeSnapshot——合并前 mergegate 比对用，MVCC 事务 ID 类比：快照=审查时的读版本，比对=提交前确认没人插队）。
   - **进度用语统一节点名**：呈报与 briefing 稿报进度 / 所处环节用 `references/stages.md` 节点名（如「现在卡在 code review，阻塞项还剩 1 个」）——节点自带使用者定义，不另展开。
5. **合并动作**：
   - merge-first：用户确认 → `cd <主仓库根> && git merge --no-ff <任务分支>`。**状态不在此手改**——等部署扳机（第 6 步 `commit --deployed`）机械翻 verifying；无部署约定的项目保持 active 直至验收翻转（`accept --pass`）。
   - verify-first：完成 6→7 且用户"验收通过"后执行本步合并 → 合并完成即跑 `tf.mjs accept <id> --pass` 翻 merged（脚本强制「分支已并入主分支」前置，翻转失败=合并没做完）。
   - **合并竞态防护（两路径同）——合并三门（MERGE_GATE，v2.58.0 双门+门三渲染证据 v2.81.0）+ 端局排队锁（MERGE_LOCK）**：合并动作前先跑 `node <skill目录>/scripts/tf.mjs mergegate <task-id>`——**门一快照（文件级分类，v2.59.0）**：main 现值 ≠ task.json.mergeSnapshot 时按「main 自快照以来的变更文件 × 本任务读写集（spec 改动文件集合声明 ∪ 影响面地图反引号资产，matchPath 匹配）」分类——**未触碰读写集 = 黄**（用户拍板 2026-10-11 免重审：变更清单强制过目 → 任务分支 `git merge <main>` 同步 + `snapshot` 刷新快照再过门，跳过第 3 步重审）；**命中读写集 = 红**（他人已合入且动了你的地盘 → 回第 1 步：任务分支 `git merge <main>` 解冲突，重跑第 3 步审查时**逐文件核对 spec 影响面地图对应行**，`snapshot` 刷新快照再过门）。黄红都 exit 1——刷新快照后幂等秒过，保住「三门全绿才进 lock」不变量；**无快照在档 = 红**（fail-closed，v2.81.0——审查呈报落稿后 `snapshot` 登记，缺档不再放行，2026-10-27 对抗审查 A2）；读写集均无机读声明 → 无法分类按红（补声明再过门，禁静默放行）。**门二越界**：分支 diff 文件超出 spec「改动文件集合声明」（matchPath：目录声明尾 / 覆盖子孙、文件声明不当前缀）= 红（二选一：`req-confirm` 落痕补声明 / 收窄 diff 拆出多余改动——防「改 A 没回归带坏 B」）。**门三渲染证据（v2.81.0 升授锁硬门）**：diff 触及样式载体（.vue 的 `<style>`/@media 或 .css/.scss/.less 文件）而任务 attachments/ 无渲染证据（图片，或 md/json 记录含「截图/量测/render」）= 红（补数据态真实渲染截图+可见内容采样描述再过门；证据质量归哨兵 RENDER_EVIDENCE_GATE（validate-render-evidence.sh）与人工过目，本门只保证无证据不得进端局）。三门全绿 → `tf.mjs lock merge --task <task-id> --session <本会话ID>`（v2.81.0 合并硬拦截 2.0：lock 授锁时**现场重算三门**（快照 fail-closed/越界/渲染证据）——纯函数只读 git 事实与任务档案，**不消费任何落盘门状态**（v2.80.0 的 `.gate-state/` 落盘校验机制已随版移除，伪造落盘文件无效）；**无豁免旗标**，未绿一律拒绝授锁，恢复路径=按门指引修到全绿；被拒=他人持锁或门未绿 → 排队等候；陈旧锁 → 强占并报告）→ **lock 后再跑一次 mergegate（同哈希幂等秒过——关掉「门过锁空窗被插队」的 TOCTOU 窗口）** → `git merge --no-ff` → 落定或中止后 `tf.mjs lock merge --release`。把「互相追赶」变「排队 + 三门」（活锁防治，2026-09-23 审查定性的唯一机器级互卡点；双门机械化 2026-10-11 用户拍板，三门+现场重算 2026-10-27 对抗审查后定案）。
   - **合并落定后失效传播（STALE_CHECK，v2.59.0）**：`git merge --no-ff` 落定后跑 `node <skill目录>/scripts/tf.mjs stale`（全量扫本项目 active/verifying 任务：main 自各任务基线 baseCommit 的改动 × 其读写集求交）——命中者呈报用户一行（⚠ 影响面漂移，点名文件与任务）；**不写其他任务的 .taskflow 目录**（硬规则 4）——重验由该任务自己的会话在 resume 第 5 步触点完成。只读命令，lock --release 前后皆可。
   - **验证分级（v2.89.0，DEPLOYMENT_PROFILE）**：`lock merge` 授锁路径三门现场重算全绿后追加输出一行「验证分级」——读 `project.json.deployment` 三键，经 schema 真身（references/schemas/project.schema.json，枚举/分级注解唯一出处）映射本次合并适用的验证档次（①文档配置直接合 ②共享测试套 ③临时实例+干净数据副本 ④任务级完全隔离缓做）+ verify 原文；未登记=ℹ「下次建档补问」。**纯信息不拦**——档次的执行仍归第 6 步部署/验证清单与 conventions 验证纪律。
 6. **推送与部署（按约定）**：有 remote → 按约定 push 主分支（未约定时问一次）。**执行远程部署命令之前，先向用户展示完整命令清单并获确认**（高影响动作；清单本身属五类正式呈报——落 `.taskflow/<id>/briefing-部署清单.md` 过 PLAIN_SPEECH_GATE 门，硬规则 24）。**部署必经唯一入口 `node <skill目录>/scripts/tf.mjs deploy --branch <部署分支> [--web-only] [--version V]`（DEPLOY_ENTRY，DEPLOY_GATE v2.42.0 四件套①，硬规则 23）**——门禁（deploy-preflight：实况核验+血统门+verifying 让位）内嵌于入口，红=拒绝执行（并集优先：先 merge 线上任务分支再构建，禁止直接上）；**部署分支防呆（v2.66.0）**：commands 含 main 检出断言的项目 `--branch` 非 main → 入口拒绝（静默空转防呆——构建 main 同内容镜像实物不变，2026-10-16 实证），merge-first 项目固定 `deploy --branch main`（deploy-gate.md「部署分支语义」），绿=按 project.json deploy 配置逐条执行命令（自带备份/回滚点步骤）→ ssh 实测新包 md5 自动 `--record` 登记（不登记=下次 I17 对账必红）；`--dry-run` 空跑门禁不部署。先 `--dry-run` 呈报命令清单（与用户确认清单合并），确认后去 `--dry-run` 实部署。项目未装 DEPLOY_GATE 或缺 deploy 配置 → deploy 入口拒绝并引导（`mech install DEPLOY_GATE` + 配置模板）；**绕过入口的手工部署 = 漏登记 = doctor I17 实况对账必红**（双包事故根因：血统门本可拦，部署会话没跑 preflight——治法=物理上跳不过）。verifying 期间非并集/非本体部署让位（预检机械拦）——细则唯一载体 references/deploy-gate.md。部署后按验证清单**逐项过**，每项结果记入本任务 `progress.md`（崩溃/换包/回滚各记一行）；每步入口指纹/版本留 checkpoint 注记。
7. **用户最终验收（归档的前置条件）**：呈现部署与验证结果 → 用户明确确认通过 → **跑 `node <skill目录>/scripts/tf.mjs accept <task-id> --pass`**（机械落 `status=merged` + `mergedAt` + index 同步；前置=分支已并入主分支，脚本强制；verify-first 下本步的实际执行点在回 5 合并完成之后，见路径头；**verifying 任务的中断恢复统一从第 6 步续起——resume.md 第 9 步与本步口径一致**）→ 才允许归档。任一环节失败或用户不认可 → **停在当前环节、保持 `verifying`，不翻转不归档**；修复落点 = **任务 worktree**（分支已并入 main 的，在任务分支修复 → 快速自查增量 diff → `git merge --no-ff` 再并入 → 回本步）。**驳回处置（verify-first 无 merge commit 可 revert 的形态，v2.53.0）**：用户明确否决且不再修 → 收口路径「先并集合入 main → 立即 `git revert -m 1` 撤销 → 从 main 重建替换包部署 → `accept --pass` 归档」——被否决代码短暂过 main 但立即回退，线上以 revert 后包为准；禁「删掉任务分支了事」（删分支会让让位门降级信息级=后续部署静默滚回，对抗审查实证）。**同一验收点第 3 轮失败 = STUCK升级门**：建议 revert 回退（data.md 状态机撤销路径）或另立新任务（resume.md 第 10 步），禁续打转。中断后恢复（resume.md 第 9 步）直接从本步续，第一动作重呈 `tf.mjs accept` 验收简报。**merged 后的整体撤回诉求**：跑 `node <skill目录>/scripts/tf.mjs revert-plan <task-id>` 生成 Saga 补偿方案（只读不执行——逐条 `git revert -m 1` 与档案 `unmergedAt` 注记落 `<taskDir>/revert-plan.md`，执行需用户逐条确认）。
8. **归档 + 汇报**：校验 decisions.md **无未晋升条目**（晋升在 checkpoint 完整版第 0 步当场完成；发现漏晋升 → 现在补）；`status=merged` + `mergedAt` 已由第 7 步 `accept --pass` 机械落定——此处核对 task.json 与 index 两处一致（I1），不一致跑 `reconcile --fix`；**归层**：`node <skill目录>/scripts/tf.mjs archive <task-id>`（搬入 archive/ + journal 三件套归位）——**status=merged ≠ 归档完成**，状态同步与物理归层都做完才允许汇报「归档完成」（实证：某会话只做了前者就汇报完成，journal 平铺根层三天无人察觉）；清理按 anchor：`managed` → **自动移除任务 worktree**（`git worktree remove`，不询问——merge/验收/归档全通过后它已无价值；**verifying 期间禁止提前移除**；git 拒绝移除 → 禁用 --force，报告原因交用户）、分支保留 `git branch -d`（禁 -D）作追溯；`attached` → **绝不自动删除用户的分支或外部 worktree**，只归档任务文档。**沉淀一问**：本次是否产出值得 mint 成 managed skill 的可复用流程？有 → `manage_skill` 落一笔或呈用户定夺；无 → 明确「无沉淀」跳过（经验归纳只覆盖被纠正场景，成功路径的经验收口靠此问）。**服务清理**：本任务起过的 dev 服务全部停掉（停服动作归编排层）+ `node <skill目录>/scripts/tf.mjs svc release <端口>` 释放 services.json 租约——别的任务可能正等着这个端口让位。最后一行汇报：合并结果 + 验证结论 + 决策沉淀清单 + 清理情况 + **续迭代入口**（照抄 `tf.mjs archive` 输出的入口句与待办种子——用户下次开新会话直接复制「@taskflow 继续 <task-id> 的迭代，做…」重入（前缀保证技能确定性触发，不赌模型自发识别），由 resume.md 第 10 步接住）。

**small 快路径（5 步，替代上面 1-8）**：① 先轻量 checkpoint（开发尾已存且无新改动可跳——merge 前存档义务挂点）→ 同步基线 + 读约定 + **同步后重跑决策组合门脚本**（同第 1 步，防并行任务新合入决策）→ ② 验收 + 全量 diff 自查（单循环修复）→ ③ **一次呈报**：审查结论 + 风险 + 验收结果 + 「归档将移除 worktree」→ 用户一句话确认（第 4/7 步两道闸的信息合并呈报，**闸不删、只去重复呈报**）→ ④ 合并（竞态防护同上；按约定 push 或问一次）→ ⑤ 归档 + 汇报（轻量 checkpoint 覆盖全程；决策晋升校验 + `tf.mjs accept <id> --pass` 机械翻转（合并后跑，前置「已并入主分支」此时天然满足——**禁手改 status**，v2.21.0）+ **归层 `tf.mjs archive`（merged ≠ 归档完成）** + 清理；汇报含**续迭代入口**句——照抄 archive 输出）。**边界（对抗审查实证高危）**：本快路径仅适用 **merge-first 或无部署约定**项目；**verify-first 项目（先部署验收后合并）禁用快路径**——部署与真机验收不可压缩，走全路径 6（部署，`--deployed` 翻 verifying）→ 7（用户真机验收）→ 5（合并）→ accept --pass；verify-first 下 ③ 的「用户一句话确认」只是呈报闸，不能替代部署后的真机验收表态（对 diff 表态≠对部署产物表态）。

**并行子任务的合并**（split.md 产生的）：按同样顺序（含 small 快路径适用性）把 `task/<id>/<n>-<slug>` 合回 `task/<id>`（同步对象改为任务分支），子任务 worktree 合并完成后**自动移除**（git 拒绝则报告原因，不 force）；全部子任务归档后再走本节任务级 merge。
