# 拆分与子代理派发（medium / large 档）

**何时拆**：涉及 ≥3 个独立关注点，或 ≥2 个子系统可并行，或用户明确要求。small 档不拆。

**拆分粒度（每个实现单位）：**
- 单一职责，一句话能说清
- 可独立验收（有明确验收命令/标准）
- 涉及文件集合明确、尽量不与其他子任务重叠
- 小步可验证（2-5 分钟级别的人类工作量粒度）

**流程：**

1. 每个子任务从 `templates/subtask-spec.md` 生成 `subtasks/<n>-<slug>/spec.md`。**必须自包含**：执行者只能依赖这份文档与代码库，不依赖任何会话记忆（背景一句话、目标、验收、涉及文件、约束与禁止事项、产出要求）。
   涉及 UI 的子任务：按 references/domain.md 把 `frontend-design` 的设计方向要求写进约束节。
2. **★先 checkpoint 整个计划，再派发★**（铁律 2）。
3. **隔离判定表：**

| 情况 | 隔离方式 |
| --- | --- |
| 子任务相互独立、文件集合可能重叠、要并行 | 每个子任务独立 worktree + 分支：`git worktree add ../<repo>-<task-id>-<n>-<slug> -b task/<task-id>/<n>-<slug>` |
| 子任务有依赖（B 需要 A 的产物） | 串行（按依赖序），同一任务 worktree 内执行 |
| 纯只读调研（不改代码） | 不建 worktree |

4. **派发**：用 subagent 能力（实现用 general，调研用 explore）。子代理 prompt 必须包含：spec 全文 + 工作目录（worktree 路径）+ "只做本子任务范围内的事；完成后报告：改动文件清单、验收命令运行结果、遗留问题"。
5. **每个子任务完成后，编排层两阶段审查**（读其 diff：先 spec 合规、再代码质量；清单同 merge.md 第 5 步）。审查不过 → 打回子代理修；过了 → task.json 标 done。
6. 并行子任务的分支按 merge.md 末段合回任务分支；全部完成后走任务级 merge。
7. task.json subtasks[] 状态全程同步。
