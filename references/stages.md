# 流程节点命名表（使用者语言层）

> 本文件是节点正式名称与使用者定义的**唯一真相源**——其他文件禁复述定义、只引用节点名（呈报稿、跨文档描述进度时同此）。
> **节点 ≠ 状态**：节点是一条需求从提出到交付的流程语言（给使用者对号用）；task.json 状态机（active/verifying/merged/archived）是跨会话里程碑账本，doctor I 系列不变量只挂状态——**节点不进状态机**，防状态机膨胀成流水线日志。
> **命名与措辞定稿（2026-10-10 用户过目拍板）**：「可行性评估」（「分析」并入定义，不另立名）；「验收通过」（与既有词汇验收标准 / accept 同词，不用「验证通过」）；「人工确认部署」（不用「部署确认」）；「技术方案评审」「code review」保留原文（用户原词）。
> 来源：腾讯 OK 平台端到端研发实践一文逐节点对照——11 节点中 9 个 taskflow 已有对应物，本表做的是给既有机制贴使用者友好的标签，不是新造流程。

## 节点清单

| 节点 | 使用者定义 | 背后机制 |
| --- | --- | --- |
| 用户需求 | 你说出想要什么，一句话也行——这是整条链的起点，后面每一步都是把它做准、做出来。 | 意图识别表路由 → new-task |
| 需求评审 | AI 像采访一样把需求问清楚：先复述自己的理解请你纠偏，再顺着回答挖模糊点，直到「做什么、为谁做、关键规则、怎么算做完」都有答案。 | pipeline.md 访谈 + REQ_BASELINE 链 PRD |
| 可行性评估 | 开工前先答三问——需求有没有着落、改动能不能在本仓库闭环、要用的依赖齐不齐；任何一问不过就停下来呈报，不默默开工。 | 可行性门（new-task.md 第 3 步：三问 + 红线清单）+ 档位判定 + DEP_ASK_GATE |
| 仓库关联 | 确定活儿落在哪个代码库、哪条分支上干：建独立工作目录和任务档案；要踩着另一个未合并任务的成果时，以它的分支为基线。 | worktree + baseBranch 链式 |
| 技术方案评审 | 把「怎么改」写成施工图再动代码：关键决策一次一问请你拍板，拿不准的点集中列待确认，高风险决策确认前自我找茬；你点头才开工。 | spec 关键决策质询（含找茬自审）+ 确认门槛 + split.md 施工纪律 |
| code review | 代码写完后换个视角挑毛病：对照规格书查漏做、多做、做偏，顺着改动查上下游和同类波及，核对安全与契约。 | merge 门三阶段 + 审查三轴 |
| 修复 | 把阻塞项改掉，改前先答三问（输入从哪来、结果谁消费、同类还有几处），改完重跑审查直到清零；同一道坎三次过不去就升级请你拍板，禁止无限重试。 | 修复循环 + 扩散三问 + STUCK 升级门 |
| 测试 | 三层各有各的门：开发中关键逻辑先写会失败的测试再实现，合并前逐条跑规格书里的验收命令，部署后真机走查。 | 先红后绿 + spec 验收命令 + 项目测试床走查（如 .testbed） |
| 人工确认部署 | 上服务器前必须你点头：先看完整命令清单，部署门禁（血统、签名、实况对账）全绿才发——这道门防静默滚回，不可绕。 | DEPLOY_ENTRY + 部署墙 |
| 验收通过 | 部署后你真机试用并明确表态，通过任务才算过验收关；不通过走打回循环：指认位置、修复、复验。 | verifying 状态 + accept --pass |
| 合并和清理 | 收尾三件事：分支并回主线、任务档案归档、工作目录删除（分支保留可回退）；台账销项后这个需求才算交付完毕。 | merge + archive + worktree 清理 |

## 使用规则

1. **呈报进度统一用节点名**：五类正式呈报（plain-speech.md §4）与 merge 呈报报进度 / 所处环节时用本表节点名——节点自带使用者定义，呈报里不必再展开解释（与词表「术语首现带白话」同源：已定义词汇直接用）。
2. **禁止另造近义词**：同一环节不换叫法（验收通过 ≠ 验证通过、人工确认部署 ≠ 部署确认——三处拍板见页首）；新节点须先入本表再使用。机器输出的既有压缩形「已合并归档」（tf.mjs ls，指本节点「合并和清理」的完成态）在本表登记豁免，不算近义漂移。
3. **节点顺序是叙述序不是严格时序**：code review 与修复是循环、测试分布在开发内（先红后绿）与验收面（真机走查）两处——以定义里的机制锚点为准，不按表格行号推执行顺序。
4. **机制层术语不动**：各 references 内部既有叫法（访谈 / spec 质询 / 三阶段审查等）是对内机制名，保留不改写——本表是使用者 / 呈报层语言，映射关系就在「背后机制」列。
