# testing — 测试策略（AI 时代的测试理论落地）

> 知识层：写 spec 时按此选层、审查时按此复检、报告红了按诊断六步走。运行时选择器是 `tf.mjs testplan`；执行永远在专家工具（mvn/vitest/Testcontainers/项目测试床/判卷）。
> 原则一句话：**每层管自己的失败模式；跨层都拦不住的，说明不变量没有显式写下来。**

## 一、十项传统理论 → AI 时代落地总表

传统理论的元假设是"不信任人"；AI 开发后变成**两层不信任**：防 AI 犯错 + 防 AI 写的测试也犯错。

| 传统理论 | 人的时代防什么 | AI 时代落地 |
| --- | --- | --- |
| 分层金字塔 | 人工改动引入回归 | 失败模式归属不变；写测试成本趋零→层可更厚；**新增层**：AI 输出判卷（非确定性）、轨迹评估（中间步） |
| 测试类型学（冒烟/sanity/回归/探索性） | 不同时机不同投入 | 冒烟=部署后 smoke；sanity=探针；回归=defect→test 硬规则；**探索性=走查穷举+对抗性审查（doubt-driven）** |
| 测试设计技术（等价类/边界值/判定表） | 人偷懒只写 happy path | AI 同病且更自信 → spec 每条 AC **标注设计技术**（见下） |
| 变异测试 | 验证测试有效（人跑不动） | **从奢侈品变必需品**：AI 写的测试可能永绿空洞；merge 门抽检 mutant kill |
| 测试左移 | 测试早介入选评 | **spec 即测试**：边界与影响面/用户验收节；TDD=防幻觉对齐（RED 证明测试在测，GREEN 证明实现满足） |
| 基于风险的测试 | 资源按风险分配 | testplan 的命中规则：共享组件/契约/AI 输出→加重 |
| 覆盖率 | 度量充分性 | 贬值+变质：行覆盖可被刷量欺诈 → **变异得分 > 行覆盖** |
| 测试数据管理 | 环境一致性 | 新原则：**数据无关性**——断言"相等"不断言"值"（历史先例：哨兵与数据耦合必腐） |
| 缺陷管理 | 记录与流转 | **闭环化**：bug→永久测试（防复发）→scout 索引（防重犯） |
| 非功能测试 | 性能/安全专项 | 性能分段契约；安全测试待接（后续迭代） |

**不需要搬的**：测试用例管理系统（用例住代码里）、大规模 UAT 剧本（收敛为用户验收节）、回归套件维护成本论（新风险是测试意图漂移，靠 RED 纪律锁）。

## 二、验证栈（AI 时代金字塔的真身）

人的时代一层不信任；AI 时代是嵌套验证——每层验证它下面那层的产物：

```
accept（用户真机验收）      ← 验证整体
  ↑ 判卷                  ← 验证 AI 生成的非确定性输出
    ↑ 变异测试             ← 验证 AI 写的测试是否真的在测
      ↑ 测试套件           ← 验证 AI 写的实现
        ↑ 契约/不变量断言   ← 验证两个产物之间的一致性（同源）
```

## 三、失败模式归属表（选层依据）

| 层 | 管什么 | 抓不到什么 |
| --- | --- | --- |
| 单元测试 | 纯逻辑错、边界条件、模板拼错 | 跨模块不一致（mock 掉依赖后各测各的"对"） |
| 接口/集成测试 | ★ 不变量断言的**本命层**：同一响应内两数同源、字段契约、权限、422/404 | 前端渲染、样式 |
| 前后端 E2E | 用户旅程、字段对不上、null 崩、权限链路 | 数字语义（除非显式数值断言） |
| 视觉回归 | 样式崩、错位 | 数字语义（截图不知道 74≠532） |
| 契约测试 | 后端改字段前端没跟 | 业务口径错误 |
| AI 判卷 | 编造实体、与数据不符、禁词 | ——（非确定性输出的专属层） |
| 线上对账 | 慢性漂移、静默腐化 | ——（生产化后再议） |

## 四、测试设计技术清单（spec AC 标注用）

写每条验收标准时声明用了哪种——防 happy-path 病：

- **等价类划分**：输入分几类，每类取代表值（正常/异常/空）
- **边界值分析**：最易错的边缘——0/空/极大/超长/负数/刚好越界；**降级路径（非 git/无数据/命令缺失）都是边界值**
- **判定表**：多条件组合（变更类型 × 输出门），防漏组合
- **状态迁移**：有状态机的流程（任务状态、弹层开关）
- **同源断言**：两个来源必须相等（数据无关，长生不死）

## 五、诊断六步（报告红了的规定动作）

测试报告（冒烟红/哨兵红/判卷 FAIL）进来 →

1. **拿证据指针**：时间窗、复现命令、日志位置——报告没带就先补齐（测试床报告格式另立任务补强）；本地机械部分可直接跑 `tf.mjs diagnose <task-id>` 装配证据包（提交史/改动集/测试资产/最近运行）；
2. **拉上下文**：服务器日志按时间窗查、测试床操作实录、相关提交的 diff；AGENTS.md 红线：平台疑似问题必须完整记录请求/响应（凭证脱敏），不得只凭摘要下结论；
3. **判性质**：`tf.mjs scout <症状关键词>` 查修过没——修过=🔁回归 → **先查为什么复发（被回退？条件漏了？），禁止直接再补丁**（硬规则 9）；🆕首次；〜相似可参考；
4. **列假设**：出方案前先列 2~5 个排序假设（各带可证伪预测），呈报用户后再逐个验证——单假设禁直接出方案（与 SKILL.md 报障行、diagnosing-bugs Phase 3 同口径；实证：merge 冒烟红首轮锁死构建缓存，第 3 轮 STUCK 才停，多假设呈报可第一轮从用户处拿到「今天动了出网防火墙」直接命中）；
5. **缩范围**：graph 查报错代码的反向依赖与受影响流——别只盯报错那一行；
6. **出方案**（见下节格式）。

## 六、方案输出格式（修复方案的标准模板）

```markdown
## 问题定位（证据链）
<症状> ← <日志/实录证据（带时间窗）> ← <根因代码位置>
## 根因
<为什么错——设计层原因，不止"哪行错">
## 方案
- 设计层方案（优先）：<改结构/改契约/改同源机制>，理由：<>
- 最小补丁（仅当）：<设计层改动风险> 时可接受，须附后续设计层跟进项
## 影响面
<graph 反向依赖点名；共享组件的其他使用方行为不变的保证（盘点按第八节五步，禁凭记忆列）>
## 防复发
<本 bug → 永久测试一条（写明落在哪层——按第三节归属表选）>
```

## 七、腐化防线（审查清单用）

- 断言**相等**不断言**具体值**（数据无关才长生——历史先例）；
- 新测试变异抽检 ≥1 个 mutant kill（AI 测试可能永绿空洞）；
- 哨兵/测试资产与功能代码**同批提交部署**（禁分批）；
- RED 纪律：新测试先跑红再转绿（防改断言迁就实现的意图漂移）。

## 八、消费方盘点（语义变更动手前硬流程，硬规则 14）

改任何承载语义的代码前（函数行为/字段口径/枚举/公式/位序单位/协议格式——含 bug 修复），五步：

1. **grep 实证列消费方**——搜函数名/字段名/常量名，逐条记「文件:行号 + 消费性质」（展示/计算/存储/透传/协议）；禁凭记忆列
2. **跨层追透传**——A 层透传给 B 层时两端都算消费方（透传 ≠ 无关：语义变了下游展示口径跟着变）
3. **逐方核对影响**——每条消费方回答「该变更改变其行为/口径吗」；消费方多点分布 = 逐点同步改；全部收敛到同一点 = 才有资格「修一处」
4. **清单落痕**——checkpoint/findings/呈报附「消费方 → 影响 → 处理」表；merge 审查对照 spec「边界与影响面」节核对（无 spec 小档对照 findings 清单）
5. **禁自我豁免**——「展示层问题/纯文案」不构成跳过理由：是否纯展示由第 1 步清单判定，主观分类错误正是漏盘根因

## 九、强制矩阵（按变更类型；pipeline.md 分类承接，merge 阶段二机械核对）

> 来源：superdx test-enforcement 吸收（2026-09-28，taskflow 替代路线 Phase 3）。类型词 = pipeline.md 内部分类。

### 后端 TDD（绝对强制，无豁免）

| 变更类型 | 流程 |
|---|---|
| new_feature | RED-GREEN-REFACTOR |
| req_change | 先更新测试反映新行为 → 确认失败 → 改实现 → 确认通过 |
| bug_fix | 先写回归测试复现 → 确认失败 → 修复 → 确认通过 |
| refactor | 确认既有测试覆盖 → 重构 → 测试仍绿（GREEN-GREEN） |

验证方式 = git log 测试先于实现（merge 阶段二动证，v2.33.0）。

### 数据迁移 TDD（条件强制——碰 schema/回填/seed 才触发）

四断言全过才算 GREEN：①fresh-up 空库迁到 head ②幂等（重复执行无副作用）③回滚往返（down→up，不支持 down 的工具验基线重建）④回填断言（行数/非空约束/默认值按查询断言，**仅命令退出码 0 不算通过**）。迁移测试在独立载体执行（内存库/容器/临时库，测后销毁），**NEVER 用开发库验迁移**；违反记 TDD_VIOLATION。无迁移任务零负担。

### 前端测试（绝对强制）

| 变更类型 | 要求 |
|---|---|
| new_feature | 新组件组件/集成测试 + 关键流程 E2E |
| req_change | 更新既有测试反映新行为 + 影响流程则 E2E |
| bug_fix | 回归测试先红后绿 |
| refactor | 既有覆盖确认 → 重构 → 仍绿 |

E2E 触发（任一即触发）：页面路由/导航变更、跨组件交互、关键用户流程。样式/布局变更须截图对比或视觉断言。UI 一致性按 domain.md 领域技能检测走（缺件走 DEP_ASK_GATE 硬规则 22，禁静默降级）。

### 文档同步（所有类型；缺失 = 门控失败）

新增/修改 API → `docs/design/{域}/api.md`；新增/修改表 → `database.md`；修改用户流程 → `docs/prd/shared/ux-flows.md`（无该目录结构的项目按 conventions 对应产物落位）。

### 测试性能（触发才查；排查范围仅测试代码）

阈值参考：单子任务 >30s；批次 >20 文件且总时长 >60s；全量 >2min（小项目）/ >5min（中大型）。反模式速查：真实 I/O（TP-01）、fixture 过量（TP-02）、sleep>100ms（TP-03）、冗余覆盖（TP-04）、全应用启动（TP-05）、缺并行（TP-06）、setup 重序列化（TP-07）。检出 → 报告附「测试性能分析」段 + 修复建议，用户确认后修，修复后全绿。

## 十、同类排查（缺陷确认点硬流程，硬规则 25——CLASS_SWEEP_GATE）

**触发点（任一）**：用户打回 / 第三者审查 blocker / 测试红——**动手修之前**，不是修完之后。

**扩散三问（必答，答案落 findings.md「扩散面清单」）**：

1. **上游**——坏结果的输入/前提从哪来（谁给它喂的数据/配置/调用序列），它们干净吗？上游脏 = 这里只是症状点，根因在上游。
2. **下游**——这个缺陷的产物被谁消费了，消费方需要同步修/迁移/重算吗？（盘点方法同 §八消费方盘点，grep 实证禁凭记忆）
3. **同类**——grep 同模式还有几处：缺陷先术语化成可 grep 的技术特征（硬规则 12：现象+根因术语+修法），再全仓搜；**同类 >1 = 逐处修或逐处注记**（注记须带理由），禁止只修报告的那一处。

**产出契约**：「扩散面清单」= 上游结论 / 下游结论 / 同类命中（文件:行号）+ 每条处置，落 findings.md；**修复 diff 附清单（merge.md 第 3 步修复循环核对，缺 = 阻塞项）**；CHANGELOG 修复类条目（触发词：修复的 bug／修复 bug／bugfix／bug fix／修复缺陷／热修复／hotfix，大小写不敏感，含标题行）**条目块内**必含「同类排查：」行（唯一实例+证据 / N 处已修）与「出现次数」——条目级块解析、仅检锚点「决策组合门落地」之上受管区（之下祖父豁免），validate-changelog.sh 收尾机械检查（v2.49.0 两轮对抗加固后的口径）。

**与 §八分工**：§八是**变更触发**的写侧盘点（我要改语义，先列谁消费它——动手前）；本节是**发现触发**的读侧排查（缺陷被发现了，先扫同类与上下游——修复前）。两个触发点同时命中时，先 §八 后本节。

**宿主提醒**：TASKFLOW_GUARD H——子代理报告（task-result 消息，v2.61.0 来源限定）含 blocker/阻塞特征时，宿主注入三问提醒（只提醒不拦：普通对话/图例/自家提醒不触发；报告内否定语境仍可能误提醒——特征检测有误报率）。
