# 原型/页面视觉自查（呈报前硬性流程）

> 来源实证：bagua-trend-twodigit-20260922 原型 4 轮返工才达标——根因是「呈报前无标准、无自查」，每轮问题都靠用户指出。本文件把它变成硬流程：**先立标准 → 真渲染自查 → 全项通过才呈报**。

## 触发点（不执行 = 呈报不合格，用户可直接打回）

- 前端 UI 任务的原型/设计稿产出后、呈报用户之前
- 实现完成的页面部署/呈报之前（同一套标准复用）
- 返工后再呈报之前（按上轮用户打回的问题清单逐项复验）

## 第 1 步：先立「设计自查标准」（写下来，不许心里想）

标准来源（有则必取，按优先级——改现有页任务第 2 项必列）：

1. **已拍板原型的规格表（DESIGN_SPEC_EXTRACT，硬规则 19）**：`.taskflow/<id>/design/spec-extract.json`（显式 DOM 树 + 布局语义 + 全量 computed styles）——视觉标准唯一真源；对照 = 逐项程序采样，抽查色值表不算对照
2. **App 现状基线（APP_PAGE_BASELINE，硬规则 21——改现有页任务必列）**：`.taskflow/<id>/design/baseline/baseline-<page>.json`（App 现状快照：结构树 + @color/@dimen 解析值 + 截图）——**未改区域与基线逐项对照**（结构分区/组件顺序/token 值/day-night 双值），delta 区域才走新设计；新增页面 = 产物链「不适用——新增页面」+ 同类现状页取样对照。基线与第 1 项规格表冲突 = 呈报用户裁决（App 漂移补拍板 / 原型过时回写真源），禁止自动取舍
3. **用户参考对象**：用户给了参考站/截图/竞品（如"仿 17500"）→ 逐项提取可验证特征（布局分区、连线画法、球规格、组头文案、行序……），每项一条
4. **系统既有设计语言**：读同类页面的组件样式源码，提取配色变量、组件规格（如命中球 `.circle` 22px `#F56C6C`/`#409EFF`、遗漏 `.omit-value #999`、斑马纹 `tr.even #f9f9f9`、连线 DataConnector 参数）、渲染写法（普通 CSS 优先——内联 SVG 属性会逃过浏览器/扩展的夜间模式转换）；无基线时的兜底（有基线以基线为准）
5. **本任务 spec 已拍板项**：关键决策、用户故事验收条目

标准每条必须**可验证 + 用术语表述**（见下文「术语化规范」）。

## 第 2 步：真渲染自查（不许只看代码）

用截图/浏览器工具真实渲染，按清单逐项核对，至少覆盖七个维度：

| 维度 | 自查项示例 |
| --- | --- |
| 结构对齐 | 信息架构与参考对象/既有页面一致（如：独立维度入口 vs 页内切换——**IA 类歧义必须在此之前问用户拍板**）；布局分区、组头文案、行序 |
| 数据正确性 | 抽查 ≥2 期数据人工按口径核算（等价类+边界值：三值同卦/互异等） |
| 像素定案 | **眼见未必为实**：球色/命中/连线归属/位置类结论禁止目测定案——DOM rect × DPR → 截图像素采样比对预期色，附「元素→坐标→采样值→预期值」证据；仅布局观感可目测且注明「目测」 |
| 渲染健康 | 控制台零 error（TDZ 引用、undefined 取值等任何异常都不合格）；关键网络请求全 200 |
| 样式一致性 | 配色取自系统设计变量；组件规格对齐既有类；无内联 SVG 背景色（夜间模式兼容） |
| 交互完整性 | 窗口/视图切换、空态、契约降级、sticky 表头、横向滚动 |
| 空态可解释（感知层验收，硬规则 16） | 每个可达状态（开放类：空/分叉/降级/**默认隐藏/折叠/抽屉态**等）要么有解释载体（文案/提示行），要么 PRD 明确拍板「无解释」——禁止无解释的空行/空白；断言解释载体的可见性与文案，不是只断言数据 |
| 环境干扰排除 | 强刷排除旧 chunk 假象；检查端口/进程残留（旧 dev server 抢占 = 改动"不生效"假象） |

发现问题：逐条记录（现象 + 根因术语 + 修法），修复后**重渲染重查**，全项通过才进入第 3 步。

### 像素采样操作要点（硬规则 13 落地步骤，陷阱清单）

定案式：对每个待验证视觉事实，产出一行证据「元素选择器 → DOM 坐标 → 截图像素坐标 → 采样值 → 预期值 → 通过/不通过」。常见陷阱：

- **DPR（devicePixelRatio）**：截图是设备像素，DOM rect 是 CSS 像素，映射必须乘 `devicePixelRatio`；截图工具返回的图片尺寸 ÷ CSS 视口尺寸可反推实际 DPR
- **滚动/全页截图偏移**：全页截图时 rect 需加 `scrollX/scrollY`；元素不在视口先 `scrollIntoView` 再截再采，别用"全页模式"坐标直接混采视口截图
- **canvas 坐标系**：球画在 canvas 内时无独立 DOM 元素，用 canvas 的 rect + 内部绘制坐标换算；注意 canvas 是否被 CSS 拉伸（width/height 属性 vs CSS 尺寸不一致时按比例缩放）
- **抗锯齿**：取球心采样（半径中心），避开边缘 1-2px 过渡带；比对用色距容差（如 RGB 各通道差 ≤30 或欧氏距离），不做精确等值
- **缩放与环境**：浏览器 zoom≠100% 会让映射整体错位，采样前归位；夜间模式扩展会改页面色值——预期色取 `getComputedStyle` 当前实际生效值，不是写死的设计稿值

## 第 3 步：呈报附自查记录

呈报内容 = 原型/截图 + 「标准清单 + 逐项核对结果（通过/不通过+术语描述）」。用户可对**标准本身**提异议（标准错了改标准，不算返工）。

## 术语化规范（硬要求）

问题、结论、决策记录（findings/progress/handoff/呈报）一律用**标准术语/技术名**，禁止含糊口语。接手 Agent/子代理只看记录就能执行。

| ❌ 含糊口语 | ✅ 术语表述 |
| --- | --- |
| "连线不对/没线" | 连线语义错误：组内折线（zigzag，上行命中球心连下行命中球心）误写为同列竖连；另 SVG 绘制函数列索引 off-by-2 取 undefined 抛异常，innerHTML 未执行 |
| "页面打不开/乱了" | UniversalIndicatorPage 白屏：watch getter 引用后置声明的 reactive 变量（TDZ ReferenceError），setup 中断 |
| "颜色跟别人不一样" | 夜间模式不一致：斑马纹用 SVG `<rect fill>` 内联呈现属性，逃过浏览器/扩展的 CSS 转换；应改 tr.even + CSS 背景 |
| "改了没生效" | 旧 dev server 进程抢占端口，浏览器连接到旧实例（旧 chunk）；lsof 查端口后清理 |

## 正反实证

- **反面**：bagua 原型 v1 未提参考特征清单（结构没对齐）、v2 视觉问题靠用户列清单、v3 连线 off-by-2 + 组内折线语义错误、v4 配色未取系统变量、最终又打回 IA 与夜间模式——**共 4+2 轮**，全部可在第 1 轮自查拦下
- **正面**：第 4 轮做了「与 17500 原版并排截图逐项对照」，一次过——该方法应第 1 轮就做
