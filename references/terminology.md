# 术语对照表（自造词 → 传统术语）

本表是 taskflow 自造词的唯一对照源：看不懂的词先查这里。维护纪律三条——
① 新自造词进 SKILL.md/references 前必须先在本表登记；确能用传统术语直呼的，直接用传统术语；
② 文档与输出首现写法统一为「自造词（传统术语）」，之后可只用自造词（与存量档案、命令名兼容）；
③ 命令名、字段名、机制 token（park/mergegate/I16 等）是接口契约**不改名**，本表只做理解映射。

## 一、状态与流转（对应数据库事务 / 工单状态机词汇）

| 自造词 | 传统术语 | 一句话定义 |
| --- | --- | --- |
| 扳机（部署扳机） | 触发器（trigger） | 命令执行时自动附带的状态变更动作，如 `commit --deployed` 落部署记录时把任务迁到等验收 |
| 状态翻转 | 状态迁移（state transition） | 按状态机规则从一态迁到另一态；「翻转唯一写路径」= 状态字段只允许经触发器命令修改 |
| 唯一写路径 / 写侧 | 单一变更入口 | 等同「禁直改库」：task.json 的 status 只认扳机命令，手改即违规 |
| 搁置（park / unpark） | 挂起 / 恢复（suspend / resume） | 工单移出在办队列但档案与分支全保留，必须留原因，可随时恢复 |
| 归层（archive 归层） | 归档（冷热数据分层） | 已完结任务从活动区（根层）搬入历史区（archive/），过程记录一并归位 |
| 游离（游离工作） | 未登记资源（孤儿资源） | 仓库里真实存在但不在台账（index/task.json）登记的分支、worktree 或改动 |
| 敞口（I16 敞口） | 未闭环风险（风险敞口） | 已上线部署但代码未合并的窗口期——线上跑的是分支包，随时可能被回滚覆盖 |
| 收口（收口链） | 闭环（闭环整改） | 把遗留风险按固定步骤处理完：合并 → 重部署 → 验收，一步不缺 |
| 接力（压缩接力 / 接力线索） | 交接班 | 会话压缩或中断时，把活任务上下文移交给下一会话的摘要线索 |
| 簿记 | 台账登记 | 对关键动作做台账式留痕（写 status 的同时同步 index、写事件日志） |
| 占号 | 资源预占 | 版本号计数器的预占登记，防并行发版撞号 |
| 让位 | 资源避让 | 部署预检发现他人任务正在线上等验收时，先合并对方再部署 |
| 双活 | 并行作业 | 多会话/多任务同时在同一仓库工作（双活数据中心同源词） |
| 紧急中止 | 急停（emergency stop） | 进行中危险动作的即时叫停——先停执行并报告落点（做到哪一步/生效了什么），不做状态操作，处置随后再议 |

## 二、门禁与管控（对应质量门禁 / 配置管理词汇）

| 自造词 | 传统术语 | 一句话定义 |
| --- | --- | --- |
| 门 / 闸（mergegate 双门） | 质量门（quality gate）/ 卡点 | 流程强制检查点，不通过不放行；「双门」= 快照门 + 越界门连检 |
| 快照门 | 审查基线过期检查 | 合并前比对「审查时的主线基线」与「当前主线」——基线被他人推进且动了你的文件，旧审查作废须重审 |
| 越界门 | 变更范围审计 | 实际改动文件超出申报清单即卡住，防计划外变更（scope creep） |
| 物理墙 / 硬拦（J 墙 / A 墙） | 强制控制 | 宿主层技术强制（模型绕不过），区别于「靠自觉」的制度约束——技术强制 vs 制度约束的双层防线 |
| 门编号（I16 / J / K） | 检查项编号 | 每条管控措施的固定编号，便于点名与回归（类似检验批编号） |
| 采纳（mech 采纳） | 基线登记 | 项目在 project.json 登记已安装的机制及其版本，作为对账基线 |
| 漂移（采纳漂移） | 配置漂移（configuration drift） | 项目登记的版本 ≠ 技能当前版本，或登记说有而实物没有——须刷新或清理 |
| 双源（isVerifying 双源） | 双字段交叉校验 | 顶层 status 与 deploy.status 任一命中即判定成立，防单字段被漂移后漏判 |
| 埋点（T 模块） | 探针 / 打点采集 | 在读取动作上挂只计数的探针，产出使用统计（信令探针同源词） |
| 档位（off / warn / enforce） | 控制级别 | 同一检查点的三档强度：跳过 / 警告放行 / 强制拦截 |
| 零干扰 | 非涉事不介入 | 非 taskflow 项目、非涉事文件一律原样放行，检查器默认不介入 |
| 守门（TASKFLOW_GUARD） | 宿主侧自动检查 | 装在 omp 里的门禁系统，把关键纪律从「模型记得做」降到「宿主强制做」 |
| 渲染（mech install 渲染） | 产物生成 | 按模板把机制产物生成到项目指定位置（模板 → 实物） |
| 牵连排查 | 影响面分析（impact analysis） | 动手前列全消费方清单、呈报必含「影响面：已核 N 处/未核 0 处」——判改动波及面，不等用户问（判定点 J19） |
| 数据真空（真空形态） | 空数据场景（empty state / 无参照数据） | 数据驱动功能拿不到可对比的输入（首期无上期/上游没产出/被中间层吞掉）——行为必须显式：有数据就对比，没数据不硬凑（判定点 J20） |
| 全量路径盘点（全量盘点） | 路径枚举（path enumeration） | 宣称不可行前，把正规/权限面/绕过三层路径连同影响面与合规标注并列呈报，合规判断归用户——「拿不到 X」≠「不可行」，先盘已持权限能否合法达到同一目的（判定点 J21） |
| 权限面 | 已持权限/凭据面（privilege surface） | 已持有、可合法动用的权限与密钥总称（服务器 root/配置密钥/DB 直连）——「凭据不在我手里」不是「不可行」的判据（判定点 J21 配套） |
| 证据源分级 | 证据层级（evidence hierarchy） | 实测>代码>文档>推断的强度序，回答基于可用最高强度源，链式推理一跳一实证，实证与「推断，未验证」分开标注（判定点 J22） |
| 功能面取舍（功能面裁剪） | feature-surface trade-off | 对用户直接可见的产品形态做的取舍（复用完整形态/带不带既有提示数字），归用户逐项拍板，成本论证只是输入（判定点 J23） |
| 渲染自证 | 渲染验证（render verification） | 真实渲染环境的截图+程序采样证据，文件级证据（测试通过/类型检查）不得替代——改 UI/视觉代码的交付必附（判定点 J24） |
| 接口面 | API 调用面（API call surface） | 页面从加载到复现动作实际触达的全部接口总集——页面级排查先抓全量接口面建「页面↔接口」映射再定位，禁凭话语猜单接口开查（判定点 J25） |
| 改动面（改动面枚举） | 变更范围界定（change scope enumeration） | 需求实现前枚举：涉及页面清单→逐页接口面→文件清单，呈报含「改动面：N 页面/M 接口/K 文件」；同时是 J19 影响面盘点的输入（判定点 J26） |
| 容量评估 | 上下文容量对照（context budget assessment） | 预计代码面规模对照单会话上下文容量，超限或接近显式拆分（写集不相交）禁硬塞——评估先于实现（判定点 J26 配套） |

## 三、账务与对账（对应计费对账 / 台账管理词汇）

| 自造词 | 传统术语 | 一句话定义 |
| --- | --- | --- |
| 对账 / 账实对账 | 对账（reconciliation） | 台账记录与实物/实况逐项比对，不一致即红灯（标准词） |
| 补登 | 补录 | 台账该记而漏记的，事后补一行留痕 |
| 漏网 | 漏记 | 台账缺失的记录——对账要抓的主要对象 |
| 呈报 | 报审 | 按固定结构把方案/风险/结果正式呈给用户决策 |
| 拍板 | 签认 / 决策确认 | 用户对方案的最终表态；验收拍板 = 用户签字 |
| 打回 | 验收退回 | 用户验收不通过退回修复循环，状态保持在途 |

## 四、本就是标准术语，无需对照

状态机、终态、幂等、快照、基线、对账、乐观锁、租约（lease）、Saga / 补偿事务、责任链、
检查点（checkpoint）、工作树（worktree）、端局（电信交换同源词，指合并排队的关键窗口）、
观察者（事件日志 events.jsonl 的设计模式）、触发器（即「扳机」的规范译法）。
